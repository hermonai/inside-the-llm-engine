## Questions

1. What does one forward pass over *k* tokens of a sequence cost relative to
   one token — the price of a verification pass? (Chapters 22, 24)
2. What does prompt-lookup speculation gain on text that repeats its prompt,
   and on text that does not, at temperature 0 and 0.8? (Chapters 22, 24)
3. Are greedy outputs identical with and without speculation? (Chapter 22)
4. How does the gain change with four concurrent requests? (Chapter 24)
5. What does a separate, smaller draft model cost and gain? (Chapters 23, 24)

**Conditions.** The machine was busier than in the earlier records: when
checked before the runs, the owner's Docker virtual machine was using about 2.5
CPU cores, and the
one-minute load average was 4.2–5.8 at each experiment's start (five-minute
average 6.0–11.4; swap 16.5–19.9 GB used; `conditions.log`). Every comparison
is therefore paired: baseline and speculative servers ran side by side and
requests alternated between them (`ngram`, `exact`, `concurrent`), or server
configurations alternated in the order none, draft, n-gram, n-gram, draft,
none (`draftmodel`). Absolute speeds are lower than in the Part II and III
records; the ratios are what the book uses.

## Commands

```bash
llama-bench -m <3B> -p 1,2,3,4,5,6,8,12,16,32 -n 0 -r 5 -o json
llama-bench -m <8B> -p 1,2,3,4,5,6,8,12,16,32 -n 0 -r 5 -o json
llama-bench -m <draft> -p 1 -n 0 -r 5 -o json
python3 spec_probe.py <ngram|exact|concurrent|draftmodel> <outdir>
```

`spec_probe.py` (with `serve_probe.py` from the Part III record, extended to
run two servers on different ports) sends chat requests to
`/v1/chat/completions` with `cache_prompt: false` and records the server's
timings, including `draft_n` and `draft_n_accepted`. The workloads are four
prompts built around one 218-word passage written for this probe: repeat it
exactly (*quote*), rewrite it replacing "batch" with "group" (*edit*),
summarize it in three sentences (*summarize*), and an unrelated 200-word story
(*free*); `exact` adds six more prompts.

### Greedy exactness (`exact`)

Ten prompts, 300-token limit, baseline against prompt lookup. Nine outputs
were identical. The tenth (a translation into French that repeated itself;
203 of 203 drafts accepted) was identical up to the speculative run's end,
which came 45 characters before the baseline's. The probe did not record the
token counts of this pair; an early stop at the 300-token limit is what the
accounting below predicts for a run whose accepted drafts cross the limit.

### Accounting

At `d006858` the server adds all of a pass's accepted tokens to `n_decoded`
before emitting them and stops at the first end-of-output or length condition
(`update_slots`, speculative branch). Two consequences in this record: the
reported `predicted_n` of speculative runs exceeded the baseline's for
identical texts (250 against 245 tokens for quote, 254 against 245 for edit),
which would inflate the server's own tokens per second by 2–4%; and a request
that reaches its length limit inside an accepted block stops short of it (the
French case above). The book's ratios use the baseline's token counts.

## Limits

- One machine under load from other work; the pairing controls drift but not
  the level. Each configuration ran two or three times.
- The draft pair is not a matched family: different training and
  vocabularies, translated by the server. A same-family drafter (for example
  Llama 3.2 1B for the 3B) would accept more; it was not on the machine and was
  not downloaded for this record.
- Prompt lookup's gains depend on the prompt repeating in the output; the
  quote and edit tasks were chosen to show that case, and summarize and free
  to show the opposite.
- No EAGLE-family drafter was measured: at `d006858`, llama.cpp declares an
  EAGLE-3 draft type whose drafting function is a TODO.
