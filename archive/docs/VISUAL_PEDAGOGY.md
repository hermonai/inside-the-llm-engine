# Visual pedagogy

Extend the existing chapter contract rather than create a competing curriculum.
Before rewriting, state the reader's question and storyboard the objects,
mechanism, changing state, equation, memory, implementation and experiment.
Use the same values and symbols across the sequence. Show a beginner the
objects before requiring the reader to interpret the final architecture.

Each chapter needs a hero/where-we-are plate, before/after data contract,
mechanism sequence when useful, synthesis, and implementation/source links.
An operator plate states rank, shape, dtype, layout and owner. A software
architecture plate uses actual types and ownership. A measured performance
plate states units, workload and provenance; an analytical one says so.

Review gates: inventory, hero, progressive explanation, shape/math/code parity,
truthful UML, truthful memory, teaching captions, accessibility, standalone
static explanation, editable vectors, and passing build/reference checks.
These supplement all five parity gates in the [regeneration plan](../ASTRA_REGENERATION_PLAN.md).

For every chapter record a beginner, software, ML, systems, graduate and
researcher review. A beautiful figure with false pointer ownership is a
correctness defect. An animation cannot carry information missing from print.
