\chapter{Assembling a Decoder That Generates Tokens}\label{ch:decoder}
\begin{ChapterIntent}
All the pieces now exist. We will connect them into a small decoder whose
entire computation fits in a readable program. It will produce logits,
choose a token and continue from that choice. Then we will add a cache and
prove that the cache changes the work, not the intended prediction.
\end{ChapterIntent}

\section{Choose a model small enough to inspect}
Our teaching model has a vocabulary of five token IDs, model width four,
two query heads, one key/value head, two layers and an FFN width of six.
Each head has width two. The weights are deterministic values generated
from a sine function, not values learned from language.

That last sentence matters. The program is a complete numerical decoder
for the stated architecture, but its output is not meaningful language.
A random or hand-filled decoder can test shapes, causal dependencies,
position conventions and state handling. It cannot demonstrate the
language quality of a trained model.

We keep the vocabulary as IDs $0$ through $4$ so that tokenization is not
another moving part in this experiment. The prompt is $[0,1,2]$. A
trained application would obtain IDs using the tokenizer bound to its
checkpoint, then decode selected IDs with the same vocabulary. The text
boundary from Chapter~\ref{app:tokens} still applies.

The program uses pre-normalized residual blocks, full-width split-half
RoPE, grouped-query causal attention and a bias-free SwiGLU FFN.
Normalization gains are fixed to one. The output matrix is separate from
the embedding matrix. These choices define this teaching model; they are
not defaults that a loader may impose on an arbitrary checkpoint.

\section{Walk through the shapes}
Embedding lookup turns three IDs into three rows of width four:
$\mathbf X\in\mathbb R^{3\times4}$. Each layer reads this residual
matrix and emits another matrix of the same shape.

The query projection produces four coordinates per row, interpreted as
two heads of width two. Key and value projections each produce two
coordinates per row, interpreted as one head. Thus both query heads
share the same key/value head, but they can produce different scores.
RoPE rotates each Q and K head using the row's logical position:
zero, one or two. It does not rotate the value.

Each head returns two attention-output coordinates. Concatenating the
two heads restores four coordinates. The output projection maps those
four back to model width four. Add that update to the incoming residual.
Normalize the result for the FFN, expand along gate and up branches to
width six, multiply them after activation, project back to four and add
the second update.

After the second layer, normalize the final residual. The vocabulary
projection maps each width-four row to five logits. For next-token
generation we need the last row, the one associated with input token 2.
Earlier rows describe predictions at earlier prefix boundaries. They are
useful for tests, but they are not extra newly generated tokens.

\section{Account for every learned matrix}
The shape walk gives a checkable inventory. In output-row storage, each
layer's Q matrix has four rows of four coefficients. K and V each have
two rows of four. The attention output matrix has four rows of four.
Gate and up each have six rows of four, and down has four rows of six.
Count the entries rather than guessing from the number of operators:
\[
 P_{\rm layer}=16+8+8+16+24+24+24=120.
\]
Embedding and vocabulary output each contain $5\cdot4=20$ entries.
Two layers therefore give
\[
 P_{\rm matrices}=20+2\cdot120+20=280.
\]
The model has no bias vectors or learned normalization gains to add to
that count. Its unit gains are a fixed operation, not another stored
parameter vector. A hypothetical packed F32 representation of these
matrix entries would occupy $280\cdot4=1{,}120$ bytes. This is a payload
derivation, not the Python process's allocation or a checkpoint file size.

This is not a network server architecture.}
{fig:foundation-decoder-components}

The graph has repeated structure, not repeated parameters. Layer one
has the same matrix shapes as layer zero but different values.
Sharing those matrices would define another model. The output matrix
is also untied: it is not an alias of the embedding table. A tied
architecture can share the parameters while using them in different
directions; our count and generator explicitly implement the untied case.

The inspection program prints an additional concrete object: layer zero's
projection at logical position two of prompt $[0,1,2]$. Its input residual
is the embedding row for ID 2, approximately
$[0.079348,-0.192279,-0.029800,0.199959]$. The positioned queries are
approximately $[0.322253,0.091755]$ and $[0.747837,-0.235368]$.
There is one positioned key, $[0.443089,-0.332632]$, and one value,
$[0.026982,0.311392]$. These are derived from the illustrative weights,
not activations collected from a trained model.

Two query heads are visible even though there is only one key and one
value head. The second layer consumes the first layer's residual output,
not that same embedding row. Checking this transition prevents a plausible
assembly error: applying every layer independently to the original
embedding and then adding their answers. The correct stack is composition,
with one layer's result becoming the next layer's input.

\section{A complete prediction is not a complete generation}
Run the program from the repository root:
\begin{verbatim}
python3 code/foundations/lesson.py decoder
\end{verbatim}
The last logit row for $[0,1,2]$ is approximately
\[
 [0.093927,\ -0.204837,\ -0.450096,\ -0.577788,\ -0.554559].
\]
These are illustrative computations from the committed weights, rounded
for printing. Greedy selection chooses ID 0, whose score is largest.
It does not choose the coordinate with the largest absolute magnitude.
The logits can instead be passed to the sampling policy developed earlier.

Now append ID 0 to the token history and evaluate $[0,1,2,0]$. The
weights remain fixed. The input history and positions changed, so the
new final logit row can differ. Repeat this process until a token budget,
end token or another stopping condition ends generation.

The model function does not own the policy for when to stop. The
generation loop owns it. Our demonstration has no designated end token;
the tests use a fixed number of steps. Giving every toy vocabulary an
end token without defining how its parameters treat that token would
obscure the boundary we are trying to teach.

\section{Make selection, feedback and stopping three events}
Four greedy selections from the prompt produce IDs $[0,4,0,4]$ with
the committed illustrative weights. Before each selection, the evaluated
prefix has lengths three, four, five and six. After the fourth selection,
the cache still has length six: the selected final ID 4 has not been
fed back. The visible output contains four new IDs, but only the first
three of those have been evaluated to obtain another prediction.

Here is the boundary as a table. The prefix column gives the tokens
already evaluated, not merely queued or selected.
\begin{center}
\begin{tabular}{@{}lll@{}}
\toprule
Evaluated prefix & Selected ID & Further evaluation?\\
\midrule
$[0,1,2]$ & 0 & Yes, to predict another ID\\
$[0,1,2,0]$ & 4 & Yes\\
$[0,1,2,0,4]$ & 0 & Yes\\
$[0,1,2,0,4,0]$ & 4 & No, budget exhausted\\
\bottomrule
\end{tabular}
\end{center}
There is no reason to calculate the final selected token's K/V if the
caller will not request another prediction. A continuing chat may later
evaluate it when feedback resumes, provided the history and model
configuration remain consistent. The interface must record which tokens
are already represented in the cache.

{fig:foundation-decoder-feedback-sequence}

An end-token policy follows the same boundary. If a selected ID is the
configured end ID, include or suppress it in the externally visible
representation according to a declared API policy, then stop. Our trace
retains every selected ID, including the end ID, and stops before
evaluating it. It validates that an optional end ID belongs to the toy
vocabulary. This policy demonstrates control flow; it does not give a
random model trained end-token semantics.

The implementation uses a positive selection budget and a nonempty
prompt. It does not define a zero-budget prefill API. Those are deliberate
small-interface limits, not universal requirements for serving APIs.
Before every selection it compares the entire cached logit row with
full-prefix recomputation, so a wrong intermediate result cannot be
hidden by a coincidentally unchanged greedy winner.

\end{verbatim}
The output records each selection's evaluated length, logits and maximum
cached/full absolute error. On this run the maximum errors are zero.
That observation describes these Python paths and fixtures; the test

\section{First implement the expensive version}
The \texttt{Decoder.full} method embeds every input token, runs every
layer over every row, and returns a logit row for every position.
For each layer it constructs projections for the whole sequence, then
uses only the permitted prefix for each attention row.

This version has no persistent state. Calling it twice with the same
tokens and unchanged weights computes the same function. Its inefficiency
is a virtue while learning: there is no hidden cache to explain a wrong
answer. We can inspect all positions at every layer.

If we generate several tokens this way, each new call repeats work for
old positions. Causality tells us those earlier representations have not
changed. The earlier position cannot depend on the newly appended token.
We can exploit that fact, but we first need to identify exactly which
values a later query needs.

\section{Then keep only the reusable state}
A future query needs the earlier keys and values at each layer.
It does not need earlier query vectors. The \texttt{Cache} object
therefore owns one key history and one value history per layer, together
with the number of tokens already evaluated.

To append a new token, embed it and process one row through the stack.
At layer zero, normalize the row, calculate Q/K/V, rotate Q and K at
the current logical position, and append the new K/V to layer zero's
history. Attention reads that entire permitted history, including the
new entry. Apply the output projection, residual, normalized FFN and
second residual. Repeat at the next layer using its own cache.

The layers cannot share a K/V array merely because their shapes match.
Their weights differ, and each layer receives a different representation.
Likewise, two requests cannot share mutable cache histories merely
because their current lengths match. The state describes a particular
evaluated prefix under a particular model.

For the default model, each token adds two layers times two objects
(K and V) times one KV head times two coordinates: eight cached scalar
values. A packed F32 implementation would use 32 payload bytes per token.
Python lists and Python float objects take additional memory, so this
payload count is not a measurement of our program's resident size.

\section{Why caching is valid: a short induction}
Let $\mathbf x_i^{(\ell)}$ be the residual at position $i$ entering
layer $\ell$, where layer zero receives the embedding. For a fixed
model, that embedding depends on the input ID at $i$, not on any future
token. Suppose every input to layer $\ell$ at positions through $i$
depends only on tokens through its own position.

Normalization and projections operate on each row. Positioned Q/K/V
therefore inherit that dependency, with the fixed position rule included.
Attention at $i$ reads only K/V at positions $j\le i$. Its output can
depend on tokens through $i$ but not on a token beyond $i$.
The output projection, residual additions and FFN also operate on the
current row. Thus $\mathbf x_i^{(\ell+1)}$ preserves the dependency.
Induction over layers proves that extending the prefix cannot change
an already-computed row in this model.

Consequently its old positioned keys and values remain valid, and one
new query may consume them rather than rebuilding them. The proof relies
on fixed weights, fixed normalization and position rules, causal
attention and deterministic evaluation without changing stochastic state.
It is not a license to reuse caches after switching an adapter, editing
the prompt or changing RoPE configuration.

Notice that the proof establishes a real-arithmetic computation and its
dependencies. An optimized full-prefix kernel and an incremental kernel
may use different floating-point reduction orders. Numerical agreement
then needs an explicit tolerance and task-level checks. Causality does
not itself prove bitwise equality of two implementations.

\section{Name the evaluated frontier}
After evaluating the three-token prompt, the cache position is three.
It contains representations for positions zero through two. Selecting
ID 0 does not change the cache position. Only evaluating that selected
ID advances the cache to four.

This distinction is easy to lose when a generation API returns a token
and a state object together. Ask whether the returned state includes
the returned token or only the prefix that predicted it. Either interface
can be designed consistently; an engine must not mix the two conventions.
Our interface is explicit: \texttt{append(token)} evaluates its argument,
then returns logits for the next selection.

RoPE uses this evaluated position, not the token ID, batch row or
number of calls to an unrelated request. Interleaving two requests must
not advance either one's position on behalf of the other. The tests
create two caches for the same model, interleave appends and compare
each result to its own full-prefix reference.

\section{Prove that reuse preserved the computation}
At every prefix length, compare the cached result with
\texttt{model.full(prefix)[-1]}. Compare all five logits, not only the
selected token. Two erroneous rows can still have the same maximum.
Use a stated tolerance; this example uses Python float arithmetic and
the tests allow an absolute difference of $10^{-12}$.

Run that comparison across different numbers of layers, different
histories, ordinary multi-head attention and grouped-query attention.
The committed tests do this for several small configurations. They
also change a future token and verify that earlier full-prefix rows
remain unchanged. Generation tests feed back the selected token for
several steps and compare both paths each time.

These are strong state and composition checks, but the paths share
scalar primitives. If both call a wrong softmax, their agreement will
not reveal it. That is why the previous chapters have hand-worked
attention and FFN fixtures, and why the test suite includes separate
normalization, linear-map and rotation checks.

Deliberately break the cached position by resetting it before each
append in a scratch copy. The first token still works, because its
correct position is zero. Later comparisons fail. A test containing
only singleton prompts would have missed the defect.

\section{Measure saved work by counting calls, not guessing time}
Take a three-token prompt and request three predictions. The full path
evaluates prefixes of lengths three, four and five. Per layer, that
is twelve projected rows. The cached path evaluates the prompt once
and appends only two feedback tokens, giving five projected rows per
layer. With two layers the counts are 24 versus ten.

Attention does not disappear. Full-prefix causal pair counts per query
head are $6+10+15=31$. The cached path consumes row lengths
$1+2+3+4+5=15$. Multiplying by two query heads and two layers gives
124 versus 60 query--key pairs. The test wraps the actual projection
and attention calls and observes those counts; it does not merely
reimplement the formulas.

The cached count includes the prompt's serial append evaluation.
A dedicated parallel prefill path could calculate the same prompt rows
together, but our small cache does not implement that optimization.
Comparing these scalar call counts is not a latency benchmark. Weight
reuse, scheduling, reduction overhead and parallelism influence runtime.
The derivation identifies removed work without manufacturing a speedup.

During the next incremental step, all five old K/V entries remain useful
and the new entry is added. There will be six permitted keys per head.
This makes the trade-off tangible: projection work for old tokens is
removed, persistent storage grows with history, and each new attention
row still reads that history. Later chapters optimize those costs
separately rather than treating cache enablement as a complete solution.

\section{Separate an assembly oracle from a regression fixture}
The printed five-logit row is a useful regression fixture. If a change
moves it, something numerical changed. But recording that row from the
program does not independently prove it correct.
Full-prefix/cache agreement is another kind of evidence: it detects
different state/control-flow errors while leaving shared primitive errors
potentially invisible.

An independent assembly fixture can make the whole decoder tractable by
removing its two updates. Set every attention output matrix and every
FFN down matrix to zero, with biases still absent. Neither branch can
change the residual. Choose an embedding $[3,4,0,0]$ and output rows
that extract coordinate zero, extract coordinate one, subtract coordinate
one from coordinate zero, and extract coordinates two and three.
After any number of these zero-update layers, the residual is still
$[3,4,0,0]$. The final RMS normalization and output projection must give
\[
 \frac{[3,4,-1,0,0]}{\sqrt{25/4+10^{-5}}}.
\]
The test derives this answer directly and checks both execution paths
for three repeated input IDs. It can catch a missing final normalization,
an extra residual addition or a wrong output orientation. It does not
exercise nonzero attention/FFN updates, so the separate operator fixtures
and ordinary parity cases remain necessary.

The new parity sweep covers every three-token history over five IDs:
$5^3=125$ histories in each of three head/layer configurations.
Every prefix row is compared. Deliberately resetting the cached position
to zero after the first append produces a discrepancy greater than
$10^{-5}$ in the chosen two-token case; a singleton-only test passes.
The suite preserves this failure as a negative control without modifying
the valid implementation.

\section{What this decoder does not yet promise}
There is no checkpoint importer, training loop, optimized kernel,
scheduler or network server here. The cache is a growing Python list,
not paged device memory. It is bound to the decoder instance, whose
weights must remain unchanged during use. A general service would
need stronger lifecycle and mutation controls.

Even its error handling has a boundary. An invalid token ID is rejected
before cache mutation. That does not make append transactional against
every later failure. If a broken weight matrix raises an exception halfway
through the stack, some layer histories may already have grown.
A production request needs a commit/rollback or failure-retirement policy;
this teaching program assumes valid, fixed matrices and tests the stated
input rejection. Do not infer recoverability from one guarded input.

The existing Rust capstone implements a related decoder with paging,
batch scheduling and terminal events. It is useful later, after those
concepts have their own chapters. We do not make a beginner learn a
block allocator merely to understand a next-token prediction.
The small Python decoder is a transparent reference, not a new claim
that the early Rust ENGINE milestones already include these features.

\section{A model is now a concrete program}
You can now trace an ID into an embedding, through normalized residual
blocks, into logits, through selection and back into the next input.
You can also point to the state whose reuse makes incremental generation
possible. That is enough model knowledge to ask systems questions without
treating the Transformer as a black box.

The remaining chapters of Part I connect this computation to bytes,
numerical formats, hardware and experiments. They prepare the reader
to understand a roofline plot or a cache-capacity calculation as a
consequence of a program they already know, rather than a formula to
memorize.

Memory capacity & spends & Each evaluated token retains eight KV scalars in the default model; packed F32 payload would grow by 32 bytes.\\
Memory bandwidth & moves & Old projections disappear, but each new attention row still consumes its permitted history.\\
Correctness & risks & Cache identity, position, layer ownership and the evaluated frontier must agree with the model and generation policy.\\
\end{ConstraintLedger}
