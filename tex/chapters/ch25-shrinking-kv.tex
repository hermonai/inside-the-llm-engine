\chapter{Shrinking the KV Cache: MQA, GQA and Multi-Head Latent Attention}\label{ch:shrinking-kv}

\begin{ChapterIntent}
The bytes retained for one past token are partly an allocator decision and partly a
model-architecture decision. MQA and GQA share key/value heads among query heads. MLA
stores a learned latent and a small positional component, then algebraically moves
projections so decode can attend without reconstructing full per-head K/V. This chapter
derives the representations, traces one token from projection to cache to decode,
quantifies capacity and bandwidth, and states the exact boundary between a storage
optimization and a different trained model.
\end{ChapterIntent}

\OpeningSection{112 KiB versus 36 KiB for one token}

On the book's Apple M1, Llama~3.2~3B and Qwen2.5-Coder~3B had nearly identical
empty-context decode speed: 24.24 and 24.36 tokens/s. At 16,384 tokens they decoded at
10.47 and 17.81 tokens/s. llama.cpp allocated 1,792 MiB versus 576 MiB of F16 KV for
that context: exactly 112 versus 36 KiB per token
(\texttt{research/measurements/2026-09-24-m1-part5.md}).

The models are similar in parameter bytes. The difference is attention geometry.
Llama has 24 query heads sharing 8 K/V heads across 28 cached layers; Qwen has 16
queries sharing 2 K/V heads across 36. The engine cannot toggle this sharing after
loading the checkpoint. It was trained into the projections.

DeepSeek's MLA pushes the architectural decision further. Instead of retaining
expanded K/V heads, it retains a compressed latent plus a small rotary component. The
question becomes: \emph{what is the minimum sufficient state that this trained
attention layer requires from a past token?}

\Foundations{Three different things are often called ``KV compression''}{
Paging changes where identical K/V bytes live. KV quantization changes their numerical
representation. MQA/GQA/MLA change the model architecture and therefore what state is
defined to exist. Do not claim an allocator can turn an arbitrary MHA checkpoint into
GQA or MLA. Conversion requires changing weights and normally training/uptraining.
Chapter~\ref{app:qkv} establishes the query-head and KV-head dimensions;
Chapter~\ref{ch:kv-cache} prices each retained scalar. Here those dimensions
become architectural choices. A smaller number of KV heads can reduce
retained bytes without reducing the number of query heads, but the
attention kernel must implement the checkpoint's head-sharing map rather
than inventing one at run time.
}

\NapkinSection{Napkin math: bytes per retained token}

For $L$ cached layers, $H_{kv}$ K/V heads, head width $d_h$ and $b$ bytes per cache
element,
\begin{equation}
m_{\rm GQA}=2LH_{kv}d_hb .
\label{eq:ch42-gqa-bytes}
\end{equation}
MHA is $H_{kv}=H_q$. MQA is $H_{kv}=1$. GQA has group size
\[
g=\frac{H_q}{H_{kv}}.
\]
Relative to otherwise identical MHA, cache bytes shrink by $g$.

For the DeepSeek-style MLA representation used throughout this chapter, let the cached
content latent have width $d_c$ and the shared rotary key width $d_R$. Then
\begin{equation}
m_{\rm MLA}=L(d_c+d_R)b .
\label{eq:ch42-mla-bytes}
\end{equation}
There is no factor two because the latent participates in both key-score and value
reconstruction paths; the rotary component is stored separately.

For DeepSeek-V3-style dimensions $L=61$, $d_c=512$, $d_R=64$, $b=2$,
\[
m_{\rm MLA}=61(576)(2)=70{,}272\ {\rm bytes}\approx68.6\ {\rm KiB/token}.
\]

\section{Trace one ordinary multi-head token}

Let hidden state $h_t\in\mathbb{R}^{d_{\rm model}}$. Ordinary attention forms
\[
q_t=W_Qh_t,\qquad k_t=W_Kh_t,\qquad v_t=W_Vh_t.
\]
After reshaping, each query head $i$ owns
$q_{t,i}\in\mathbb{R}^{d_h}$ and each K/V head owns vectors of the same or specified
head widths. MHA has a distinct $(k_{t,i},v_{t,i})$ for every query head.

At decode step $t+1$, query head $i$ reads every retained $k_{s,i}$ and $v_{s,i}$,
$s\le t$. The past token's projection was computed once but its cache is read over and
over. This read amplification is why reducing retained bytes can affect both capacity
and token latency.

\section{MQA: one history, many questions}

Multi-query attention keeps distinct queries but shares one K/V history:
\[
H_{kv}=1.
\]
For query head $i$,
\[
\alpha_{i,s}=\operatorname{softmax}_s
\left(\frac{q_{t,i}^{\top}k_s}{\sqrt{d_h}}\right),\qquad
o_{t,i}=\sum_s\alpha_{i,s}v_s.
\]
Queries remain different; only the memory they interrogate is shared.

This distinction matters in a kernel. The same cached key tile can be reused across
many query heads. Memory traffic falls, while arithmetic per loaded cached element
rises. MQA intentionally trades some representational independence for much stronger
data reuse.

\section{GQA: make sharing a tunable architectural ratio}

Grouped-query attention partitions $H_q$ query heads into $H_{kv}$ groups. Query head
$i$ maps to
\[
j(i)=\left\lfloor\frac{i}{g}\right\rfloor,\qquad
g=H_q/H_{kv},
\]
and attends to K/V head $j(i)$.

With $H_q=8$, $H_{kv}=2$, $g=4$, query heads 0--3 share K/V head 0 and 4--7 share
head 1. The cache contains two K rows and two V rows per token, not eight each.

\section{GQA is not a runtime deduplication trick}

Suppose an MHA checkpoint happens to produce similar K heads. An engine still cannot
store one copy and point several queries at it unless the values are exactly equal and
the computation is defined to share them. Tiny differences alter attention logits and
outputs.

GQA changes $W_K$ and $W_V$ shapes. Ainslie et al.\ showed an uptraining route from
MHA to GQA by pooling K/V heads and continuing training \cite{ainslie2023gqa}. That is
model conversion, not transparent inference optimization.

This boundary is useful throughout the book:
\[
\boxed{\text{same mathematical model?}}
\]
If yes, an engine optimization should pass a differential oracle. If no, quality must
be evaluated as a new checkpoint/model architecture.

\section{Byte accounting agrees with the M1 allocation}

For Llama~3.2~3B:
\[
2(28)(8)(128)(2)=114{,}688\ {\rm bytes}=112\ {\rm KiB/token}.
\]
For Qwen2.5-Coder~3B:
\[
2(36)(2)(128)(2)=36{,}864\ {\rm bytes}=36\ {\rm KiB/token}.
\]
Multiplying by 16,384 tokens yields 1,792 MiB and 576 MiB, exactly the reported
llama.cpp allocations in the measurement record.

This is an important textbook checkpoint: architecture metadata predicts allocator
bytes without a profiler.

\section{The bandwidth crossover}

Let quantized model weights occupy $W$ bytes and KV state per token be $m$. Ignoring
other traffic, one batch-one decode step at context $S$ reads roughly
\[
D(S)\approx W+Sm.
\]
The cache equals weight traffic near
\[
S^*=\frac{W}{m}.
\]
Using the measured files, Llama~3.2~3B has $W\approx2.01$ GB and
$m=112$ KiB, giving roughly 17.5K tokens. Qwen2.5-Coder has $W\approx1.92$ GB and
$m=36$ KiB, giving roughly 52K.

The crossover is not a performance theorem: kernels, cache hierarchy, attention
arithmetic and batch matter. It is a first-order warning about when the retained
history can rival model-weight traffic.

\section{Why decode speed diverges with context}

A simple bandwidth model predicts
\[
v(S)=v(0)\frac{W}{W+Sm}.
\]
The historical measurement found the two 3B models almost tied at empty context, then
increasingly separated as $S$ grew. That is exactly the qualitative prediction from
their threefold difference in KV bytes/token.

At 16K, the model does not perfectly predict Llama's measured speed; the discrepancy
is useful. Bytes explain a major component, not every kernel cost. A systems textbook
should preserve the residual instead of fitting it away.

\section{MLA changes the retained object}

Multi-head latent attention starts from a learned down-projection
\[
c_t=W^{DKV}h_t,\qquad c_t\in\mathbb{R}^{d_c}.
\]
Conceptually, head-specific content keys and values can be written
\[
k^C_{t,i}=W^{UK}_i c_t,\qquad
v_{t,i}=W^{UV}_i c_t.
\]
A naive implementation could cache $c_t$ and reconstruct all expanded K/V every time.
That would save capacity but spend enormous repeated compute.

The key systems idea is \emph{projection absorption}: move fixed linear maps across
the contractions so decode can operate against the latent directly.

\section{Absorb the key projection into the query}

For content score,
\[
q_{t,i}^{\top}k^C_{s,i}
=q_{t,i}^{\top}W^{UK}_i c_s
=(W^{UK\top}_i q_{t,i})^{\top}c_s.
\]
Define
\[
\widetilde q_{t,i}=W^{UK\top}_i q_{t,i}.
\]
The engine computes $\widetilde q$ once for the current query, then dots it directly
against every cached $c_s$. No expanded content key needs to be stored or reconstructed
per past token.

This is ordinary associativity of linear algebra, but it radically changes the data
path: move computation to the one current query instead of expanding every historical
entry.

\section{Absorb the value projection after reduction}

Ordinary value aggregation is
\[
o_{t,i}=\sum_s\alpha_{i,s}W^{UV}_ic_s.
\]
Because $W^{UV}_i$ is independent of $s$,
\[
o_{t,i}=W^{UV}_i\left(\sum_s\alpha_{i,s}c_s\right).
\]
First reduce cached latents with attention weights; then apply the value up-projection
once. Again, the expanded per-token values never need to exist in persistent cache.

\EngineFigure{ch25-mla-absorption}{Projection absorption moves fixed MLA up-projections away from every historical token: the query is mapped into latent space before score computation, and the value up-projection is applied after the weighted latent reduction.}{fig:ch42-mla-absorption}

\section{RoPE is the algebraic obstruction}

RoPE applies a position-dependent rotation $R_s$ to a key. If the content projection
were inside that rotation,
\[
q^\top R_s Wc_s,
\]
the matrix multiplying $c_s$ depends on historical position $s$; it cannot generally
be absorbed into one fixed query projection.

DeepSeek's decoupled RoPE separates positional information. The cached representation
contains the content latent $c_s$ plus a comparatively small rotary key $k^R_s$. A
query has corresponding content and rotary components, and the score is the sum of the
two contributions.

This is a deeper architectural lesson: compression became possible because the model
was designed so that the position-dependent operation does not contaminate the large
compressible content representation.

\section{A concrete latent-cache record}

For the chapter's DeepSeek-style example, one layer retains
\[
[c_s\ (512\ {\rm elements})\ |\ k^R_s\ (64\ {\rm elements})].
\]
At BF16/FP16 that is
\[
576\times2=1{,}152\ {\rm bytes/token/layer}.
\]
Across 61 cached layers it is 70,272 bytes.

A useful engine descriptor therefore differs from GQA. GQA can describe K and V tensors
with $(H_{kv},d_h)$. MLA needs at least latent width, rotary width, dtype/layout and
the model-specific projection contract.

\section{Prefill and decode may prefer different algebra}

Projection absorption reduces data movement during decode, where one or a few current
queries read a long history. During large prefill, many queries exist at once. Explicit
K/V reconstruction can become competitive because reconstructed tensors are reused
across many query operations and standard highly optimized attention kernels may be
available.

Thus one mathematical attention layer can have multiple execution paths:
\begin{align*}
\text{prefill} &:\quad \text{compute-friendly expanded form},\\
\text{decode} &:\quad \text{data-movement-friendly absorbed form}.
\end{align*}
The engine must prove numerical/semantic equivalence within its chosen precision
contract.

\section{MLA raises arithmetic intensity on purpose}

GQA reduces bytes by sharing heads. Absorbed MLA goes further: it reads a compact latent
but performs more arithmetic around that latent. That is often desirable because
decode has idle arithmetic while being bandwidth-limited.

This is the same resource exchange seen in speculation:
\[
\boxed{\text{spend cheap compute to avoid expensive bytes}}
\]
until batch size or multi-token verification makes compute no longer cheap.

The roofline therefore belongs in architecture discussions, not only kernel chapters.

\section{Cache capacity becomes concurrency}

If usable KV memory is $M_{\rm KV}$ and each request has average retained length
$\bar S$, a rough resident-request bound is
\[
B_{\max}\approx\frac{M_{\rm KV}}{m\bar S}.
\]
Reducing $m$ by eight can approximately multiply the KV-limited concurrency by eight,
subject to weights, activations, fragmentation, scheduler limits and other state.

This is why K/V architecture affects serving economics even if single-request latency
barely changes at short context.

\section{Paging still matters after architectural shrinking}

MLA does not replace paged memory. Architectural shrinking determines bytes in one
logical token record. Paging determines how those records are allocated, shared and
reclaimed across variable-length requests.

Likewise prefix caching still matters: a shared 68.6-KiB/token prefix is cheaper than a
shared 320-KiB/token prefix, but reuse can still avoid both storage duplication and
prefill computation.

Keep the planes separate:
\[
\text{architecture}\rightarrow\text{logical state}
\rightarrow\text{numerical format}\rightarrow\text{physical allocation}.
\]

\section{Quantization composes multiplicatively---approximately}

If a GQA cache moves from 16-bit to 8-bit storage, equation~\eqref{eq:ch42-gqa-bytes}
halves its payload. Combining architectural head sharing with numerical compression
can therefore multiply capacity gains.

But metadata, scale granularity, padding and kernel workspace prevent exact
multiplication at allocator level. More importantly, quantization introduces numerical
error whereas GQA/MLA are the model's trained definition. Their correctness contracts
are different.

\section{Tensor parallelism exposes a hidden cost of very few K/V heads}

If $H_{kv}$ is smaller than tensor-parallel degree $P$, simple head sharding cannot give
each rank a unique K/V head. Implementations may replicate K/V state, use different
attention/data parallelism, or shard along sequence/context.

An architecture that minimizes logical cache bytes can therefore create physical
duplication under an ill-matched parallel layout. Always distinguish
\[
\text{logical bytes/token}
\quad\text{from}\quad
\text{aggregate bytes across ranks}.
\]

This becomes particularly important for MLA-like one-latent-head execution.

\section{Cache sharing across layers is another axis}

Head sharing is not the only architectural reduction. Cross-layer schemes let several
layers reuse K/V state. Hybrid models replace growing attention state in some layers
with fixed recurrent state. Sliding-window layers cap retained history.

The accounting generalizes:
\[
m_{\rm token}=\sum_{\ell\in\text{growing layers}}m_\ell
+\text{fixed per-sequence state}.
\]
Chapter~\ref{ch:hybrid-models} develops the second term; Chapter~\ref{ch:long-context}
develops bounded windows and eviction.

\section{Correctness tests must match the claimed transformation}

For an engine-only optimization of MLA algebra, compare absorbed and explicit forms on
identical weights/inputs. They should agree within a numerical tolerance.

For MHA$\rightarrow$GQA conversion, that oracle is inappropriate because the model has
changed. Test model quality and training claims instead.

For KV quantization, compare against higher-precision cache and measure numerical/task
error.

Three techniques all reduce memory; they require three different validation protocols.

\section{Failure modes worth making executable}

A serious lab should catch:
\begin{enumerate}
\item wrong query-to-K/V group mapping;
\item accidental replication counted as sharing;
\item using packed-row/head index where group index is required;
\item applying value up-projection before rather than after the weighted latent sum;
\item treating a position-dependent RoPE projection as absorbable;
\item omitting the rotary cache from MLA byte accounting;
\item counting logical savings while tensor-parallel ranks duplicate the cache.
\end{enumerate}

\section{An engine-facing attention descriptor}

A generic inference engine should not hard-code ``K tensor + V tensor'' as the only
cache schema. A useful model-derived descriptor can express:
\[
\begin{aligned}
&\text{query heads and widths},\\
&\text{retained components per token},\\
&\text{component dtypes/layouts},\\
&\text{query-side transforms},\\
&\text{post-reduction transforms},\\
&\text{position-dependent components},\\
&\text{sharing/parallel ownership}.
\end{aligned}
\]
Then pagers and kernels consume the descriptor rather than pretending every model has
MHA-shaped state.

The model defines retained components and transforms; quantization chooses representation; the pager assigns physical blocks; the attention backend consumes both logical and physical metadata.}{fig:ch42-cache-contract}

\section{Operational observability}

At model load, log derived cache bytes/token by layer family and compare them with
allocator capacity. At runtime expose logical cached tokens, physical allocated bytes,
replication factor across ranks, cache dtype, attention backend and context-length
distribution.

For MLA also record execution path (absorbed decode versus expanded/prefill path where
applicable). Without this, a deployment can silently retain the architectural capacity
benefit while losing the expected bandwidth benefit to a fallback kernel.

\LedgerSection
\begin{ConstraintLedger}
Memory capacity & buys & MQA/GQA reduce K/V heads; MLA stores a latent plus positional component. Smaller logical records increase KV-limited concurrency.\\
Memory bandwidth & buys & Fewer retained bytes are read for every historical token during decode; the benefit grows with context.\\
Compute & spends & Shared-head reuse raises arithmetic per loaded byte; absorbed MLA deliberately trades additional transforms/contractions for lower history traffic.\\
Latency & trades & Long-context decode can improve substantially; unsuitable kernels, large batches or projection overhead can move the bottleneck back to compute.\\
Correctness & requires & GQA/MLA are trained model definitions; only algebraic execution rewrites of the same model are subject to strict differential equivalence.\\
Cost & trades & More requests/longer contexts fit per accelerator, but specialized kernels, parallel layouts and model-specific integration increase engineering cost.\\
\end{ConstraintLedger}

\LabSection{prove sharing and absorption separately}

The Rust lab in \texttt{code/labs/ch25-shrinking-kv/} uses tiny deterministic vectors.
It first constructs MHA/GQA head mappings and proves the byte formula against an
explicit element count. It then evaluates a miniature latent-attention value path in
two mathematically equivalent forms:
\[
\sum_s\alpha_s(Wc_s)
\quad\text{versus}\quad
W\left(\sum_s\alpha_sc_s\right).
\]
An independent scalar oracle checks equality. Deliberately broken variants use the
wrong GQA group and apply a token-dependent ``projection'' after absorption, showing
why fixed linearity is the required invariant.

The lab is not a DeepSeek implementation and makes no GPU-performance claim.

\HappenedSection{architectural bytes predicted measured allocations}

The strongest evidence in this chapter is deliberately mundane: metadata and
equation~\eqref{eq:ch42-gqa-bytes} predict the measured llama.cpp allocations exactly
for the two 3B models. The resulting context-depth speed divergence is directionally
consistent with the bandwidth model.

MLA represents a more aggressive co-design. DeepSeek-V2 introduced the latent-cache
construction and projection absorption \cite{deepseek2024v2}; subsequent DeepSeek
models retain the approach. Engines consequently need MLA-specific attention paths
rather than treating it as an unusual GQA tensor shape.

\FrontierSection{2026-10-05}

The direction is toward less growing state per generated token: fewer K/V heads,
latent caches, cross-layer sharing, bounded windows and hybrid recurrent/attention
layers. The important systems trend is not any one acronym. Model architects are
co-designing the \emph{state interface} with inference engines.

That suggests a durable engine abstraction:
\[
\boxed{\text{model-defined retained state}+
\text{engine-defined representation/allocation/execution}.}
\]
Chapter~\ref{ch:mixture-of-experts} now changes a different axis: instead of shrinking
state, it makes only a subset of model parameters active for each token, turning
routing, expert locality and all-to-all movement into first-class engine problems.
